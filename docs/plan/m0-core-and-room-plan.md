## Part A — `:core` music types (pure Kotlin, tests first, assertions read as sentences)
Package root `com.betterappmafia.apophenia.core`.

1. **pitch/**: keep `SpelledPitch`; add `Accidental` ASCII tokens (`bb b n # x`) parse/format; `PitchClass` value class (0–11) used only where no spelling exists; `Pitch.frequency(a4Ref = 440.0, centsOffset)`; octave-label setting (C4 default / C3) as a formatter, MIDI number always available.
2. **interval/**: `Interval(number, semitones)` with derived `Quality` (perfect class 1,4,5,8,11,12: -1 dim/0 P/+1 aug; major/minor class: -2 dim/-1 m/0 M/+1 aug; doubly aug/dim representable); compound intervals; `between(a, b)`; `SpelledPitch + Interval` (letter-based) and `-`. Tests: A4 (4,6) ≠ d5 (5,6); every simple interval above all 35 roots.
3. **degree/**: `DegreeToken` grammar (optional `bb b n # x` + number 1–15) ↔ Interval (`bb7`=(7,9), `#11`=(11,18), `b13`=(13,20)); parse/format round trip.
4. **spelling/**: `spell(root, degrees)` = letter from number, alter from semitones; triple accidental → respell root enharmonically unless context forces it (then allow doubles); default root table C Db D Eb E F F# G Ab A Bb B for unkeyed pitch classes. Trap tests (from the skill): F major Bb; C°7 = C Eb Gb **Bbb**; E7#9 **F##**; C7#9 **D#**; G# major **B#**; Ger+6 in C = Ab C Eb **F#**; tritone sub of G7 = Db F Ab **Cb**; altered scale's two spellings.
5. **catalog/**: `scales` and `chords` as Kotlin data (versioned; JSON assets later only if needed [Claude]) using degree tokens: all modes of major / melodic minor / harmonic minor, pentatonics, blues, whole tone, both octatonics, bebop family, harmonic major modes, double harmonic etc. (design doc §3.1); chord qualities from design doc §3.2 incl. essential/omitOrder. Test: every catalog chord and scale on all 35 roots spells with no triple accidentals and correct pitch classes.
6. **chord/**: `Chord` structure mirroring MusicXML 4.0 `<harmony>`: root (SpelledPitch no octave) | numeral, `Kind` enum of the 33 MusicXML kind values (exact spellings incl. `Neapolitan`, `Tristan`), ordered `Degree(value, alter, type add|alter|subtract)` with the spec arithmetic (alter/subtract relative to the kind's degree; add relative to a dominant chord), bass, poly, quality id, typed text. Tests: kind+degrees → pitches for the research doc's encodings (C7(b9,#11), C7alt, Cm7b5, C6/9, Cadd9, C(no3), C/E, D/C polychord, N.C.); quality ↔ kind+degrees table tested both ways.
7. **rhythm/**: exact `Rational` durations, dots 0–3, tuplet stack (any n:m, nested), ticks at 960/quarter, `TimeSignature(groups, denominator)` (7/8 = [2,2,3]/8, 6/8 = two beats), `Tempo(bpm, beatUnit)`, swing ratio. Tests: rhythm arithmetic, nested tuplet durations, beats-per-bar for compound/additive meters.
8. **instrument/**: `Tuning` (spelled open strings in string order, re-entrant ukulele), capo, fret count, written-vs-sounding transposition; presets from plan §6.4 (guitar standard, drop D, D standard, DADGAD, open G, open D, 7-string; bass E/D standard, drop D, drop A, 5-, 6-string; ukulele). `TabNote(string, fret, pitch)` with pitch = open + capo + fret. Tests: preset notes, ukulele order, written pitch an octave up for guitar/bass.
9. **transpose**: transpose pitch/chord by an interval and respell for the target key (C→Eb: D7 → F7, not E#7).

Out of M0 (later milestones, noted so they aren't forgotten): chord-symbol **parser** with dialects and the **renderer/typesetting** (needed when chords are typed on the Board, M2); MusicXML/ChordPro/MIDI I/O (M5/M7); naming engine, Roman analysis, voicing/fingering, set-class tools (M5/M6); McGill Billboard / ChoCo fixtures (with the parser).

- Location [Claude]: Room in `:app` under `com.betterappmafia.apophenia.data` for now (CLAUDE.md fixes three modules); move to a `:data` module later if it grows. Room 2.8.5 + KSP (newest stable KSP compatible with Kotlin 2.4.21 — look it up, don't guess). `exportSchema = true`, schema JSON committed under `app/schemas/` so every later migration is tested against it.
- Scope of v1 [Claude, ask Christopher only if a field implies a product decision]: tables M1 needs, designed so later tables arrive by migration:
  - `scrap` (id, type: recording|lyric|text|chord_chart|tab|midi|sheet, title, created/edited times, project_id nullable = recorded in a project, show_in_library flag, deleted_at for 30-day trash)
  - `take` (scrap_id, letter A/B/C…, starred, audio file path, duration, sample rate, metronome grid JSON nullable, latency_used_ms nullable)
  - `tag` (scrap_id, kind: tempo|key_mode|instrument|meter|tuning|capo|loop_mode|keyword, value (ASCII tokens), source: user|metronome|analysis) — user source always wins; analysis never overwrites
  - `group` + `group_member`
  - `project` + `project_ref` (project_id, scrap_id, per-project settings: trim, loop points, gain, fades, conform, offset — JSON column with its own format version)
  - `app_setting` (key/value)
  Board blocks, sync points, stacks/layers, transcriptions, stems, practice log come by migration in their milestones.
- Rules carried from earlier apps (plus skill): every stored format versioned; newer data refused, not silently dropped; per-project settings JSON sanitized after parse (clamp, NaN/Inf replaced); audio files written once, never modified.
- Tests: DAO round trips and constraint behaviour (decide JVM path — Robolectric vs Room's bundled-SQLite JVM driver — by checking Room 2.8 docs first); schema export present; trash expiry query; per-project settings isolation (changing one project's trim leaves another project and the Library untouched).
